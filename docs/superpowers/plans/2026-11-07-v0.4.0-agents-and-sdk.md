# Anchor 0.4.0 additions: non-expiring tokens, MCP + OAuth, SDK, agent skills — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add four things to release 0.4.0:
- service tokens without an expiry;
- a remote MCP server authorized by Anchor's own OAuth 2.1 server;
- the `@anchor-secrets/sdk` and `@anchor-secrets/nestjs` npm packages;
- three agent skills installable with `npx skills add`.

**Architecture:**
- **Server:** the Worker (Hono, D1) gains:
  - a nullable `service_tokens.expires_at`;
  - an OAuth authorization server in `apps/server/src/oauth/`, with tables in D1;
  - a stateless MCP endpoint `/mcp` in `apps/server/src/mcp/`. It is built on `@modelcontextprotocol/sdk`'s `WebStandardStreamableHTTPServerTransport` and calls the existing secret services with the approving user as principal.
- **Dashboard:** adds the consent page `/oauth/authorize` and Account → Connected apps.
- **New packages:** `packages/sdk` and `packages/nestjs`, built with esbuild (ESM + CJS) and `tsc` declarations, published by the existing release workflow.
- **Skills:** live in `skills/` at the repository root.

## Review Focus

Part A:
- **A revoked never-expiring token** is refused at once, and an expired dated token is still refused. Test in A1.

Part B:
- **Refresh token replay.** Presenting an already-rotated refresh token revokes the whole grant, so the newest access token stops working too. Test in B2.
- **A non-sensitive `${DB_PASSWORD}` reference** read via `get_secret` without reveal returns the literal and is never expanded. Test in B5.
- **A viewer's agent holding `secrets:write`** gets a tool error from `set_secret`, and nothing is written. Test in B6.
- **Redirect URIs.** A loopback redirect on another port is accepted. Another host, path or scheme is refused on the page and never redirected to. Test in B3.
- **Credentials at the wrong endpoint.** A session cookie, a CLI session or a service token sent to `/mcp` gets 401. An OAuth access token sent to `/api/v1/...` gets 401. Test in B5.

Part C:
- **401 from Anchor** gives `AnchorError` whose message has no token. A 503 three times fails after exactly 3 attempts. Test in C1.
- **Anchor unreachable at Nest bootstrap.** `Test.createTestingModule(...).compile()` rejects with the `AnchorError` instead of hanging. Test in C2.

Part D:
- **`npx skills add <repo> --list`** shows `anchor-cli`, `anchor-migrate` and `anchor-ci`. The documented `--skill` install selects exactly those three. Test in D4.

- **Table:** `oauth_grants(id, user_id → users CASCADE, client_id → oauth_clients CASCADE, scopes TEXT space-separated, created_at, last_used_at, revoked_at)`.
- **Table:** `oauth_codes(id = sha256(code), grant_id CASCADE, redirect_uri, code_challenge, created_at, expires_at, used_at)`.

  - `redeemCode(db, {code, now}): Promise<CodeRow | "reused" | null>`. This is a single-winner `UPDATE ... SET used_at WHERE used_at IS NULL`. `"reused"` means it exists but was already used.
  - `issueTokenPair(db, grantId, now): Promise<{accessToken, refreshToken, expiresIn: 3600}>`;
  - `rotateRefresh(db, {refreshToken, clientId, now}): Promise<{grantId} | "reused" | null>`;

  - `authenticateAccessToken(db, token, now): Promise<{userId, grantId, clientId, scopes} | null>`. It is null when the token is expired, the grant is revoked or the user is disabled.
  - `purgeOAuth(db, now): Promise<number>`.
- **Constants:** `ACCESS_TTL_MS = 3_600_000`, `REFRESH_TTL_MS = 2_592_000_000`, `CODE_TTL_MS = 300_000`.
