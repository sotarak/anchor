# Anchor 0.4.0 — Typed Values and Browser Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Anchor **0.4.0**: per-version value types (`string`, `json`, `pem`, `number`,
`boolean`, `list`) and a `sensitive` flag across the API, CLI and dashboard (Tasks 1–7), plus
`anchor login` through the browser with dashboard approval (Tasks 8–11), `anchor secrets import`
for bulk loading dotenv/JSON/YAML files (Task 12), then the release (Task 13).

**Architecture:** One shared checker/decoder in `@anchor/shared` is used by the server (validates
writes), the CLI (validates before sending, decodes for typed export) and the dashboard (form
validation). The server stores type and flag as plaintext columns on `secret_versions` and binds
both into a new AAD format (v2), so tampering fails the decrypt. Rows from before 0.4.0 keep the v1
AAD and are always read as `string` + sensitive. Browser login is a device-authorization flow: the
CLI starts a request and polls with a secret device code, a signed-in web session approves the
short user code at `/cli/login`, and the winning poll receives an ordinary `cli` session.

**Tech Stack:** TypeScript, Hono on Cloudflare Workers, D1 (SQLite), WebCrypto AES-256-GCM, zod,
commander (CLI), React + TanStack Query + Tailwind (dashboard), vitest
(`@cloudflare/vitest-pool-workers` for the server), pnpm workspaces, biome.

**Specs:** `docs/superpowers/specs/2026-11-07-v0.4.0-typed-values-design.md` (Tasks 1–7) and
`docs/superpowers/specs/2026-11-07-v0.4.0-cli-browser-login-design.md` (Tasks 8–11) and
`docs/superpowers/specs/2026-11-07-v0.4.0-secrets-import-design.md` (Task 12)

## Global Constraints

- Release version is exactly `0.4.0` in all six `package.json` files: `package.json`,
  `apps/cli/package.json`, `apps/docs/package.json`, `apps/server/package.json`,
  `apps/web/package.json`, `packages/shared/package.json`.
- Types, exact spelling and order: `string`, `json`, `pem`, `number`, `boolean`, `list`. The
  default is `string`; `sensitive` defaults to `true`.
- AAD v2 format, verbatim:
  `anchor/secret/v2|<projectId>|<environmentId>|<secretId>|<version>|<type>|<0|1>`. The v1 format
  is unchanged.
- Rejection reasons, verbatim: `not valid JSON`, `not a PEM block`, `not a number`,
  `must be true or false`, `must be a JSON array of strings`.
- Server error: `400 bad_request`, message `value is not valid for type <type>: <reason>`.
- CLI error: `Value of <KEY> is not valid for type <type>: <reason>`, exit code `EXIT.USAGE`.
- Never put a secret value in an error message, a log line, or an audit record (CLAUDE.md hard rule).
- Security-sensitive changes need failure-case tests (CLAUDE.md): every crypto/authz task below
  has tamper or denial tests.
- Code, comments, commits and docs in English. Commits follow Conventional Commits and end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; sign off with `-s` (the repo runs DCO).
- Browser login constants: request TTL `600000` ms, poll interval `5` s, at most `50` pending
  requests instance-wide, user code `XXXX-XXXX` from `BCDFGHJKLMNPQRSTVWXZ`, device code
  `newToken("anc_dc")`, stored only as `sha256Hex(deviceCode)`.
- Browser login copy (verbatim): CLI `Open <url> and confirm the code <USER-CODE>`,
  `Waiting for approval…`, `Login was denied in the browser`,
  `Login request expired; run anchor login again`,
  `This server does not support browser login; use anchor login --with-password`; dashboard
  `Only approve if you just ran anchor login and this code matches your terminal`,
  `You can close this tab and return to your terminal.`,
  `This login request expired or was already used.`
- Import copy (verbatim): `The file must contain an object at the top level`,
  `Cannot import <source path>: <KEY> is not a valid key`, `<path A> and <path B> both become <KEY>`,
  `<KEY>: <reason>`, `Imported <n> of <m>; <KEY> failed: <error>. Re-run to continue`,
  `Created <a>, updated <b>, skipped <c> existing, <d> empty in <env>:<path>`.
- Domain skills: `secrets-crypto` for Tasks 2–4 and 8–9, `building-cli` for Tasks 5–6, 10 and 12,
  `dashboard-ui` for Tasks 7 and 11.

## Review Focus

- **An invalid typed value is never echoed.** `PUT` with `{type:"number", value:"hunter2"}` returns
  a 400 whose body and logs contain no `hunter2`. Test in Task 3 (`no-leak.test.ts`).
- **An old client updates a typed secret.** CLI 0.3.x sends `PUT {value}` with no `type` on a
  `json` secret: the type is inherited and a non-JSON value is rejected. Test in Task 3.
- **A non-sensitive reference to a sensitive secret.** A non-sensitive `string` whose value is
  `${DB_PASSWORD}` is listed without `reveal` as the literal `${DB_PASSWORD}`, never expanded.
  Test in Task 4.
- **Non-sensitive values that come through an import** carry `importedFrom` and appear without
  `reveal`; a caller who cannot read the import source still gets the existing 403. Test in Task 4.
- **Changing the type in the dashboard without retyping the value.** Edit mode re-sends the
  current value; if it does not fit the new type, the sheet shows the reason under Value instead of
  a generic toast. Test in Task 7.

Browser login:

- **Two polls race after approval.** Exactly one gets the token and creates a session; the other
  gets 404, and only one `cli` session row exists. Test in Task 8.
- **The user is disabled between approval and exchange.** The poll gets 403 "Account disabled" and
  no session is created. Test in Task 9.
- **Approval with a CLI token.** A `cli` session token, sent as a bearer or pasted into the session
  cookie, or a service token, cannot approve: 403. Test in Task 9.
- **A code typed loosely.** `wdjb-mjht`, `WDJBMJHT` and ` WDJB-MJHT ` all find the request, in the
  API path and in the page's code input. Tests in Tasks 9 and 11.
- **A 0.4.0 CLI against a 0.3.x server.** `start` returns 404, and the CLI prints the
  `--with-password` hint (exit `EXIT.ERROR`) instead of a raw "not found". Test in Task 10.

Secrets import:

- **Example files with blank values.** `api_key:` (YAML null) and `{}` are reported as empty and
  never created as empty secrets. Test in Task 12.
- **Two source paths flatten to one key** (`a.b-c` and `a.b_c`): the whole import fails before any
  write, naming both paths. Test in Task 12.
- **A source key that cannot become an Anchor key** (`2fa: x` → `2FA`): it fails before any write,
  naming the source path. Test in Task 12.
- **Failure halfway.** The 3rd of 5 PUTs returns 409: exit 1 with `Imported 2 of 5; ...`, and a
  re-run creates only the remaining 3. Test in Task 12.
- **Values never reach the terminal**, including in `--dry-run`, `--json` and validation errors.
  Test in Task 12.

PEM rules: one or more blocks separated by optional whitespace; each block is
`-----BEGIN <LABEL>-----`, then lines that are base64 (`[A-Za-z0-9+/=]+`), RFC 7468 headers
(`Name: value`) or blank, then `-----END <LABEL>-----` with the same label (`[A-Z0-9 ]+`); lines end
in `\n` or `\r\n`; leading and trailing whitespace allowed. Number: the spec's regex plus
`Number.isFinite`. The checker never puts the value into `reason`.
