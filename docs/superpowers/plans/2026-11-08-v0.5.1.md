# Anchor 0.5.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `anchor login --api-url` updates the default server, a non-Anchor 404 names the server
that answered, the CLI login page is tidied, and the secret sheet gets one editor per value type.

**Architecture:**
- **CLI:** the change stays in `saveLogin`, which now knows where the URL came from, and in the
  HTTP layer's non-JSON branch.
- **Web, login page:** a shared `KeyValueList` primitive gives the CLI login page and the OAuth
  consent page the same layout.
- **Web, secret sheet:** pure helpers in `src/lib/typed-value.ts` sit behind a
  `TypedValueEditor`, which replaces `SecretValueField`. The sheet wraps the editor in an
  edit-mode "Value unchanged" row.

**Tech Stack:**
- CLI: commander and vitest.
- Web: React 19, TanStack Router and Query, `radix-ui` (Switch, ToggleGroup), Tailwind tokens
  from the dashboard-ui skill, vitest with Testing Library and msw.

**Spec:** `docs/superpowers/specs/2026-11-08-v0.5.1-design.md`

## Global Constraints

- **No new npm dependencies.** Switch and ToggleGroup come from the existing `radix-ui`
  package.
- **Dashboard styling:**
  - Every color, text size, radius and shadow is a dashboard-ui token.
  - Labels are sentence case.
  - The "Before you finish a UI change" checklist passes on every web diff.
- **CLI copy, exact:**
  - `Default server changed from <old> to <new>` (stderr).
  - `<origin> did not answer as an Anchor server (HTTP 404)`.
  - `Check the server URL; run 'anchor login --api-url <url>' to change your default`.
- **CLI login page copy, exact:**
  - "Approve CLI login".
  - "A terminal wants to sign in as <email>".
  - "Check that it matches your terminal".
  - Rows: "Device", "IP address", "Requested".
  - "Only approve if you just ran anchor login. Approving signs this terminal in as you."
- **Secret sheet copy, exact:**
  - "Value unchanged", "Reveal current value", "Replace value", "Keep current value".
  - "Format", "Add item", "Load from file", `Detected: <label>`.
  - "Hidden in lists until revealed. Turn off for plain config such as ports or feature flags."
- **Type names and help:** exactly the spec's table (Text, Number, Boolean, JSON, List, PEM).
- **Stored values:** the stored type values and the API body (`value`, `comment`, `path`,
  `type`, `sensitive`) are unchanged. Editors only produce the string the API already accepts.
- **Version:** every manifest is 0.5.1.

## Review Focus

1. **A stored list or JSON value with its own formatting** (`["a", "b"]` with spaces, or
   pretty-printed JSON) that is revealed and then saved without edits must be sent byte for byte.
   No re-serialization unless the person changes it. Pinned in Task 5 and Task 6.
2. **`--api-url` spelled differently from the saved default** (a trailing slash, a path, upper
   case) normalizes to the same origin. It prints no "changed" line and rewrites nothing. Pinned
   in Task 1.
3. **A PEM file that is binary or not PEM** (for example a DER `.cer`). It loads as text and
   shows "not a PEM block". It never throws and never uploads anything on its own. Pinned in
   Task 5.
4. **Pasted list text with Windows line endings and blank lines.** It splits on `\r?\n`, and
   rows that are empty after trimming are dropped. Pinned in Task 4.
5. **Switching the type after revealing a value in edit mode.** The revealed text carries over
   by the switching rules, and nothing is saved until Save. Pinned in Task 6.

### Task 4: Typed value helpers

**Files:**
- Create: `apps/web/src/lib/typed-value.ts`
- Test: `apps/web/test/unit/lib/typed-value.test.ts`

**Interfaces:**
- Produces, all pure:
  - `TYPE_META: Record<SecretValueType, { name: string; help: string }>`, exactly the spec's
    table.
  - `listItemsFrom(text: string): string[]`:
    - a JSON array of strings gives its items;
    - otherwise the input is split on `/\r?\n/`, and items that are empty after trimming are
      dropped.
  - `listTextFrom(items: string[]): string`: `JSON.stringify` of the items that are not empty
    after trimming, in order.
  - `formatJson(text: string): string | null`: 2-space pretty print, or `null` when the text is
    invalid.
  - `jsonProblem(text: string): string | null`:
    - `null` when the text is valid;
    - otherwise `not valid JSON at line L, column C` when the engine's message has
      `position N`;
    - otherwise `not valid JSON`.
  - `pemLabel(text: string): string | null`: the label of the first `-----BEGIN <label>-----`
    line.
  - `booleanFrom(text: string): "true" | "false" | null`.

- [ ] **Step 1: Write the failing tests**
  - `listItemsFrom('["a","b"]')` gives `["a","b"]`.
  - `listItemsFrom("a\r\n\r\n  \nb")` gives `["a","b"]`.
  - `listItemsFrom('{"a":1}')` gives `['{"a":1}']`.
  - `listTextFrom(["a","","  ","b c"])` gives `'["a","b c"]'`.
  - `formatJson('{"a":[1,2]}')` gives `'{\n  "a": [\n    1,\n    2\n  ]\n}'`;
    `formatJson("{")` gives `null`.
  - `jsonProblem('{"a":1}')` is `null`.
  - `jsonProblem('{\n  "a": }')` matches `/^not valid JSON( at line 2, column \d+)?$/`.
  - `pemLabel("-----BEGIN PRIVATE KEY-----\nAAA\n-----END PRIVATE KEY-----")` gives
    `"PRIVATE KEY"`; `pemLabel("x")` is `null`.
  - `booleanFrom("true")` gives `"true"`; `booleanFrom("True")` is `null`.
  - `TYPE_META.list` equals
    `{ name: "List", help: "Several text items, stored as a JSON array" }`.
