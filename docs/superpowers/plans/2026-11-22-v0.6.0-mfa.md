# Anchor 0.6.0 (two-factor authentication and passkeys) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** opt-in second factor for password login (TOTP, passkeys, recovery codes), step-up for
MFA changes, an admin **Reset 2FA** action, and the CLI/dashboard flows for all of it, released as
0.6.0.

**Architecture:**
- **Server:** a new `src/mfa/` feature folder holds pure primitives (TOTP, recovery codes), a thin
  wrapper around `@simplewebauthn/server`, and D1 stores (TOTP secret sealed by the root key,
  recovery-code hashes, passkeys, login tickets, WebAuthn challenges). `/auth/login` returns a
  short-lived ticket instead of a session when the user has MFA. Three anonymous endpoints
  exchange the ticket and a factor for the session. Management endpoints under `/auth/mfa` need a
  dashboard session that re-authenticated within 10 minutes (`sessions.reauth_at`).
- **Clients:** the dashboard login page gets a second step and the Account page a
  "Two-factor authentication" section (QR code via `uqr`, passkeys via `@simplewebauthn/browser`).
  The Users page gets Reset 2FA. `anchor login --with-password` prompts for a code.
- CLI browser login and MCP consent need no change: they already require a `web` session.

**Tech Stack:** TypeScript; Hono + D1 + Workers vitest pool (server); `@simplewebauthn/server`;
commander + vitest (CLI); React 19 + TanStack Router/Query + Testing Library + msw (web);
`@simplewebauthn/browser`, `uqr`.

**Spec:** `docs/superpowers/specs/2026-11-22-v0.6.0-mfa-design.md`

## Global Constraints

- Security changes need failure-case tests (CLAUDE.md): every server task's tests include the
  attack or misuse, not only the happy path. Never log, audit or echo TOTP secrets, codes,
  recovery codes, tickets or WebAuthn responses.
- **Dependencies, exact versions (no caret):** `@simplewebauthn/server` `14.1.0` in
  `apps/server` dependencies; `@simplewebauthn/browser` `14.0.0` and `uqr` `0.1.3` in
  `apps/web` dependencies; `@levischuck/tiny-cbor` in `apps/server` devDependencies at the
  version the lockfile already resolves for `@simplewebauthn/server` (test authenticator only).
  No other new dependency.
- One additive migration: `apps/server/migrations/0010_mfa.sql`. No change to secret encryption.
- **TOTP:** HMAC-SHA-1, 6 digits, period 30 s, accepted steps `s-1, s, s+1`, secret 20 random
  bytes, displayed as RFC 4648 base32 upper case without padding. A step at or below
  `last_step` is refused. URI exactly:
  `otpauth://totp/${encodeURIComponent(`${issuer}:${email}`)}?secret=${secret}&issuer=${encodeURIComponent(issuer)}&algorithm=SHA1&digits=6&period=30`
  with `issuer = `Anchor (${hostname})``.
- **TOTP secret at rest:** `seal(keyring.current.key, secret, "anchor/totp/v1|" + userId)`,
  stored with `root_key_id`, `iv`, `secret_ct`. Opened with `rootKeyFor(keyring, root_key_id)`.
  A row that does not open throws `IntegrityError` (fail closed, 500).
- **Recovery codes:** 10 codes, format `xxxxx-xxxxx`, alphabet `abcdefghijklmnopqrstuvwxyz234567`
  (index = `byte & 31`). Stored as `sha256Hex(normalized)`, where normalized = lower case with
  `-` and whitespace removed, exactly 10 alphabet characters (otherwise invalid).
- **Ticket:** `anc_mfa_` + base64url(32 bytes) (`newToken("anc_mfa")`), stored as `sha256Hex`,
  TTL `300_000` ms, deleted after 5 failures, carries `client`.
- **Factor guess limit:** `login_attempts` key `m|<userId>`, max 5 failures, window and lock
  `900_000` ms, through the existing `reserveLoginKeys`. Counted for TOTP and recovery codes at
  login and at reauth, and for failed passkey verifications. Success deletes the key.
- **WebAuthn:** `rpID = new URL(c.req.url).hostname`, `expectedOrigin = new URL(c.req.url).origin`,
  `rpName: "Anchor"`, `attestationType: "none"`, `residentKey: "preferred"`,
  `userVerification: "preferred"`, `userID = utf8Encode(userId)`, `userName = email`,
  `userDisplayName = name`. Challenges: TTL `300_000` ms, single use. Passkey name 1–64
  characters, at most 20 passkeys per user.
- **Step-up:** `REAUTH_WINDOW_MS = 600_000`. `createSession` sets `reauth_at = now` for `web`
  sessions and `NULL` for `cli`. MFA management requires `requireWebUser` plus a fresh `reauth_at`.
- **"Has MFA"** = a confirmed TOTP row OR at least one passkey (any RP ID). Recovery codes alone
  do not count.
- **Error code** `reauth_required` appended to `ERROR_CODES`, used as
  `403 { code: "reauth_required", message: "Confirm it's you to continue" }`.
- **Copy, exact (server):**
  - wrong factor: `401 invalid_credentials "Invalid authentication code"`
  - unknown/expired/used ticket: `401 unauthenticated "Sign-in expired, start again"`
  - factor limit: `429 rate_limited "Too many failed attempts, try again later"`
  - wrong reauth password: `401 invalid_credentials "Password is incorrect"`
  - password reauth with MFA on: `400 bad_request "Confirm with your authenticator app, a passkey or a recovery code"`
  - code reauth with MFA off: `400 bad_request "Confirm with your password"`
  - TOTP already on: `409 conflict "Two-factor authentication is already on"`
  - passkey cap: `409 conflict "You can register at most 20 passkeys"`
  - recovery codes without MFA: `409 conflict "Turn on two-factor authentication first"`
  - Reset 2FA on self: `409 conflict "Use your Account page instead"`; admin on non-member:
    `403 forbidden "Only an owner can reset an owner or admin"`
- **Audit actions appended** (never rename): `auth.reauth`, `mfa.totp_enabled`,
  `mfa.totp_disabled`, `mfa.passkey_added`, `mfa.passkey_removed`,
  `mfa.recovery_codes_generated`, `mfa.reset`. `auth.login` metadata `method` ∈ `password`,
  `password+totp`, `password+passkey`, `password+recovery`; `auth.login_failed` reasons add
  `mfa_invalid`, `mfa_locked`. Add `code`, `codes`, `recoveryCodes`, `secret`, `ticket`, `response`
  to `FORBIDDEN_KEY` in `apps/server/src/audit/record.ts`.
- Web tasks follow the `dashboard-ui` skill (tokens and primitive recipes); CLI tasks follow
  `building-cli`; server tasks follow `secrets-crypto`.
- Every manifest, `apps/server/src/version.ts` and the version pins are `0.6.0` at the end.

| `GET /auth/mfa` | web cookie | none | `MfaStatusDto` |
| `POST /auth/mfa/totp` | web cookie + fresh | none | `TotpSetupDto` |
| `POST /auth/mfa/totp/confirm` | web cookie + fresh | `{ code }` | `{ recoveryCodes?: string[] }` |
| `DELETE /auth/mfa/totp` | web cookie + fresh | none | 204 |
| `POST /auth/mfa/passkeys/options` | web cookie + fresh | none | `{ options }` (creation options JSON) |
| `POST /auth/mfa/passkeys` | web cookie + fresh | `{ name, response }` | 201 `{ passkey: PasskeyDto, recoveryCodes?: string[] }` |
| `DELETE /auth/mfa/passkeys/:id` | web cookie + fresh | none | 204 |
| `POST /auth/mfa/recovery-codes` | web cookie + fresh | none | `{ recoveryCodes: string[] }` |
| `POST /users/:id/mfa-reset` | owner/admin session | none | 204 |

`recoveryCodes` is present only when the change took the account from no MFA to MFA.

## Review Focus

1. **A second hostname** (workers.dev next to a custom domain): passkeys registered on the other
   host are not offered (`methods` has no `passkey` when none matches), TOTP and recovery codes
   still work, and the Account page marks those passkeys as registered on another host. Pinned in
   Tasks 8 and 10.
2. **Something changes between the two login steps** (MFA reset, password reset or change, user
   disabled): the ticket gives no session. Pinned in Tasks 7 and 11.
3. **A recovery code typed loosely** (upper case, spaces, no hyphen) is accepted once; the same
   code a second time is refused. Pinned in Tasks 4 and 7.
4. **Removing the last factor** deletes the recovery codes, and the next login needs no second
   step; removing one of two factors keeps them. Pinned in Tasks 9 and 10.
5. **The same valid TOTP code sent twice at once** (two tabs, or an attacker racing the user)
   yields exactly one session. Pinned in Task 5 (store) and Task 7 (HTTP).
