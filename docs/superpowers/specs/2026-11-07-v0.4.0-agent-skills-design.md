# Anchor 0.4.0: agent skills for Anchor users

Status: proposed (2026-11-07). Ships with release **0.4.0**.

## Intent

AI agents working in a project that uses Anchor should know how to use it correctly: run the app
with `anchor run`, never paste secret values into commands or files, migrate an existing `.env`
or YAML config, and set up CI with a service token. A small skills pack, installable with the
`skills` package (`npx skills add`), gives them that knowledge.

## Decisions (with the user)

- Three skills: `anchor-cli`, `anchor-migrate`, `anchor-ci`.
- Written with the project's `writing-skills` skill (pressure-tested against a baseline agent).
- Installable with the `skills` CLI from this repository.

## Layout

```
skills/
  anchor-cli/SKILL.md        (+ references/commands.md)
  anchor-migrate/SKILL.md
  anchor-ci/SKILL.md
```

Frontmatter: `name` equal to the directory name (lowercase, hyphens), and a `description` that says
when to use it ("Use when ..."). No `metadata.internal`.

## What each skill covers

- **anchor-cli:** checking `anchor whoami` / `.anchor.json`; reading metadata with
  `secrets list`; running the app with `anchor run -- <cmd>`; setting values from stdin or
  `--from-file` (never argv, never echo); types and `--no-sensitive`; `export` only to gitignored
  files; never printing values into the conversation; asking the person to log in
  (`anchor login`) instead of handling passwords.
- **anchor-migrate:** moving `.env` files and nested YAML/JSON config into Anchor with
  `secrets import` (dry run first, `--non-sensitive` globs for plain config, folders per service),
  then replacing values with `${KEY}` placeholders and switching start scripts to `anchor run`;
  deleting plaintext files only after the person confirms.
- **anchor-ci:** creating a scoped `read` service token (`tokens create`, `--expires-in` or
  `never` with the trade-off), storing it as the CI secret `ANCHOR_TOKEN`, GitHub Actions with
  `sotarak/anchor/setup-action`, other CI with the install script or `npx @anchor-secrets/cli`,
  pinning the CLI version.

## Installation (documented)

`npx skills add sotarak/anchor --skill anchor-cli --skill anchor-migrate --skill anchor-ci`.
The `skills` CLI also scans `.claude/skills/`, where this repository keeps its contributor
skills, so the docs always name the three skills with `--skill` (or use `--list` to see them).

## Docs

`guides/agent-skills.md` (install, what each skill does, updating with `npx skills update`), a
README line.

## Non-goals

Skills for NestJS and MCP (MCP describes its tools itself), publishing to a skills registry,
changing the contributor skills under `.claude/skills/`.
