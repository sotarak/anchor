# Anchor 0.4.0: Node SDK and NestJS module

Status: proposed (2026-11-07). Ships in release **0.4.0**. Amended by
`2026-11-08-sdk-cache-resilience-design.md` (caching, fault tolerance, `AnchorFolder`; removes
`ANCHOR_SECRETS`).

## Intent

NestJS services (zepo-engine among them) should read their configuration from Anchor without
wrapping the process in `anchor run`, and without each team writing its own HTTP client. Two npm
packages, released with the CLI at the same version.

## Decisions (with the user)

- **Two packages:** `@anchor-secrets/sdk` (framework-agnostic Node client) and
  `@anchor-secrets/nestjs` (a NestJS module built on it). Both published to npm.
- **Load at bootstrap**, no background refresh in 0.4.0.

## `@anchor-secrets/sdk`

```ts
const anchor = createAnchorClient({ apiUrl?, token?, fetch?, timeoutMs? });
await anchor.listSecrets({ project, environment, path?, expand?, includeImports? }); // AnchorSecret[]
await anchor.loadSecrets({ project, environment, path?, expand?, includeImports? }); // Record<string, AnchorValue>
```

- `apiUrl` defaults to `process.env.ANCHOR_API_URL`, `token` to `process.env.ANCHOR_TOKEN`
  (a service token, or any bearer Anchor accepts). Missing either → `AnchorError` with code
  `config`, before any request.
- Calls `GET /api/v1/projects/:p/environments/:e/secrets?path&reveal=true&expand&includeImports`.
  `expand` and `includeImports` default to `true` (same as `anchor run`).
- `AnchorSecret = { key, path, type, sensitive, version, value, importedFrom? }` (its own public
  type; it does not expose `@anchor/shared`).
- `loadSecrets` decodes typed values like `anchor export --format json`: `number` → number,
  `boolean` → boolean, `json`/`list` → parsed, others → string.
- Timeout 10 s per attempt; network errors and 502/503/504 retry twice (250 ms, 1 s). 4xx never
  retries. Errors are `AnchorError { status, code, message }` with the server's message; values,
  tokens and URLs with tokens never appear in messages.
- Runs on Node ≥ 20 (global `fetch`); ships ESM and CommonJS with types; zero runtime dependencies
  (shared code is bundled).

## `@anchor-secrets/nestjs`

```ts
@Module({ imports: [AnchorModule.forRoot({ project: "zepo", environment: "prod", path: "/shared" })] })
AnchorModule.forRootAsync({ imports?, inject?, useFactory })
class AnchorService { get<T = AnchorValue>(key): T | undefined; getOrThrow<T>(key): T; has(key): boolean; keys(): string[] }
await loadAnchorEnv({ project, environment, path?, override? }); // in main.ts, before NestFactory.create
```

- `forRoot` options = SDK client options + list options + `isGlobal` (default `true`).
- Secrets load once during module initialization (an async provider), so the app does not finish
  bootstrapping without them; a failure throws `AnchorError` and Nest aborts startup.
- `getOrThrow` on a missing key throws `Anchor secret <KEY> is not set`.
- `ANCHOR_SECRETS` injection token gives the raw record.
- `loadAnchorEnv` writes canonical strings into `process.env` (existing variables win unless
  `override: true`), for apps that read config from the environment, including `@nestjs/config`.
- Peer dependencies: `@nestjs/common` and `@nestjs/core` `^10 || ^11 || ^12`, `reflect-metadata`,
  `rxjs`.

## Release

Both packages carry the workspace version and publish from the existing release workflow with npm
trusted publishing, after `@anchor-secrets/cli`. A new package must exist on npm before a trusted
publisher can be attached: the owner does the first setup (outward; done only with approval).

## Docs

New `guides/sdk.md` (SDK and NestJS, service-token setup, a zepo-engine example) and package
READMEs.

## Non-goals

Background refresh, watching for changes, writing secrets from the SDK, browsers/edge runtimes,
`@nestjs/config` custom loader.

## Approaches considered

1. **Core + NestJS (chosen).** Non-Nest Node apps reuse the client.
2. **Core + NestJS + polling refresh.** Deferred: config that changes under a running app needs
   its own design (which values may change live).
3. **NestJS only.** Fewer packages, no reuse.
