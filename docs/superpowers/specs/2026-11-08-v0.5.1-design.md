# Anchor 0.5.1 (design)

Status: proposed. Follows the 0.5.0 release (2026-11-08).

## Intent

The owner hit a real failure right after 0.5.0 shipped:

- They ran `anchor login --api-url https://anchor.zepo.io`, and the login succeeded.
- Then `anchor projects list` failed with `Unexpected response from server (HTTP 404)`.

The cause is that `anchor login` saves the API URL as the default only when no default exists
yet. The owner's user config still pointed at `https://anchor.zepo.workers.dev`, which no longer
serves the API. Most people deploy to Cloudflare first and add a custom domain later, so this
will hit them too.

The owner asked for a 0.5.1 hotfix for this, and in the same release two dashboard
improvements:

1. The CLI login approval page (`/cli/login?code=…`) should look professional and tidy. Today
   its layout and fonts are uneven.
2. Adding a secret should be friendlier, with an input that fits each value type.

The owner handed the design decisions to the author ("agree, plan it"). Every choice below that
the owner did not state is marked **(author's call)**.

## Goals

1. `anchor login --api-url <url>` makes `<url>` the default server, and says so when it
   replaces another one.
2. A 404 that does not come from Anchor names the server that answered, so a wrong default is
   obvious.
3. The CLI login approval page reads as one calm, aligned card.
4. The secret sheet gives each value type its own editor, checks the value while you type, and
   keeps "edit without revealing" working for every type.

## Non-goals

- New value types, or changing what the server accepts.
- A code editor dependency (CodeMirror, Monaco) for JSON or PEM.
- The 0.5.0 deferred minors (they stay deferred).
- An `anchor config` command (author's call: the login fix covers the reported case; a config
  command is a feature, not a hotfix).

## Anti-goals

- A repository's `.anchor.json` silently changing a person's default server.
- A value shown unmasked, or sent anywhere, without the person asking for it.
- An edit that changes a stored value the person never touched.
- A structured editor that loses or rewrites a valid stored value (for example reordering a
  list or reformatting JSON) unless the person asks for it.

## Approaches

### Login default

1. **An explicit `--api-url` on `login` becomes the default (chosen).** It matches what people
   expect from `login --api-url X`. The `.anchor.json` guard stays as it is.
2. **Add `anchor config set api-url`.** It is more general, but nobody would think to run it
   after a working login. Deferred.
3. **Make the most recent login the default for every source.** That would let `.anchor.json`
   or `ANCHOR_API_URL` move the default, which breaks the first anti-goal.

### Typed value editors

1. **Per-type editors built on the existing primitives and `radix-ui` (chosen).** They need no
   new dependency, stay inside the Content-Security-Policy, and validate with the shared
   `checkTypedValue`.
2. **A code editor (CodeMirror) for JSON and PEM.** It is heavier, injects styles at runtime
   (which conflicts with the dashboard's CSP style handling), and only JSON benefits from it.
3. **Keep one textarea and add only validation and a Format button.** This is cheaper, but it
   does not give booleans, lists or numbers the input the owner asked for.

## Behavior

### CLI: login and the default server

- Saving the default after a successful login:
  - The URL came from `--api-url` (source `flag`) and differs from the user config: write it to
    the user config, and print to stderr
    `Default server changed from <old> to <new>`.
  - No user config yet, and the URL does not come only from `.anchor.json`: save it as today.
  - The URL came from `ANCHOR_API_URL` (source `env`) or from the prompt: keep today's behavior,
    which saves it only when no default exists (author's call: the variable already wins on
    every run, and CI should not rewrite a user config).
  - The URL came only from `.anchor.json`: never saved (unchanged).
- `--json` output of `login` adds `"defaultApiUrl": "<the user config's URL after login>"`.
  This is additive.
- The credentials for the old server stay stored. Logging out of them stays a separate,
  explicit `anchor logout --api-url <old>`.
- A non-JSON response with HTTP 404 from any API call becomes:
  `error: <origin> did not answer as an Anchor server (HTTP 404)`, with
  `hint: Check the server URL; run 'anchor login --api-url <url>' to change your default`.
  The exit code is unchanged (1). Other statuses keep today's message.
- Docs (CLI guide, "API URL") describe the new rule. CHANGELOG has a 0.5.1 entry.

### Dashboard: CLI login approval page

One card in `AuthLayout`, in this order (author's call):

```
(anchor tile)

A terminal wants to sign in as dungla2708@gmail.com  text-paragraph-sm text-text-sub

┌──────────────────────────────────────────┐  bg-bg-weak, rounded-lg, border, p-4
│               JSSV-PBDW                  │  font-mono, text-label-lg, tracking-widest
│   Check that it matches your terminal    │  text-paragraph-xs text-text-soft
└──────────────────────────────────────────┘

IP address   171.244.199.177                 │ text-paragraph-sm text-text-soft, every

                                               baseline-aligned; the IP in font-mono
                                               at the same size

[ Deny ]  [ Approve ]                            two equal-width buttons, full row
```

- The signed-in email comes from the current session.
- The warning is one compact line with an icon, using the `warning` tone at its smallest
  size; it is not a tall box.
- "Requested" is a row of the list, not a loose line under it.
- The same key-value list primitive (`components/ui/key-value-list.tsx`) is used by the OAuth
  consent page ("App", "Returns to"), so the two approval pages match.
- The other states (enter code, approved, denied, expired or used code, load error) use the same
  card and type scale. "Approved" and "Denied" show a status icon and say the terminal can be
  closed.
- Mobile width works (16px gutter, no horizontal scroll); long device names wrap.

### Dashboard: the secret sheet

Field order stays Key → Type → Value → Sensitive → Comment.

**Type picker (author's call).** A select whose items show a human name and one line of help:

| Value | Name | Help |
|---|---|---|
| `string` | Text | Any text, one or more lines |
| `number` | Number | An integer or decimal, such as 8080 or 0.25 |
| `boolean` | Boolean | true or false |
| `json` | JSON | An object, array or any JSON value |
| `list` | List | Several text items, stored as a JSON array |
| `pem` | PEM | A certificate or key block (-----BEGIN …) |

The trigger shows the name. The stored type values do not change.

**Value editors.** Each one edits the same string the API stores:

| Type | Editor |
|---|---|
| Text | Mono textarea that starts at one line and grows to 8 lines |
| Number | Single-line input, `inputMode="decimal"`, mono |
| Boolean | Two-option toggle group: `true` / `false`; nothing selected for a new secret |
| JSON | Mono textarea (6 to 16 rows) with a **Format** button (2-space indent) |
| List | One input per item, a remove button per row, **Add item**; Enter in a row adds the next one; pasting several lines into a row splits them into items. Empty rows are dropped on save. Stored as a JSON array of strings, in the order shown |
| PEM | Mono textarea with **Load from file** (read in the browser with `FileReader`, never uploaded except as the value on save) and a hint naming the detected block (`Detected: PRIVATE KEY`) |

**Validation.**
- Live, with the shared `checkTypedValue`.
- An error shows after the field loses focus once, or on submit, never on the first keystroke.
- The message is the reason from `checkTypedValue` ("not valid JSON"). For JSON it adds the
  parser's position when the browser gives one.
- Submit stays enabled; an invalid value blocks it with the error, as today.

**Switching type (author's call).** The raw text carries over, then each editor reads it:
- Number and Text: as is.
- JSON: as is, so a list's JSON stays valid JSON.
- Boolean: selected only when the text is exactly `true` or `false`.
- List: a JSON array of strings becomes its items. Any other text becomes one item per
  non-empty line.
- Switching never saves anything by itself.

**Edit mode (every type).**
- The value starts as a closed row: "Value unchanged", with **Reveal current value** (loads it
  into the type's editor, as today) and **Replace value** (opens the editor empty).
- While the row is closed, saving sends no value (unchanged, as today). Changing only the type
  is still checked by the server against the stored value.
- Once opened, **Keep current value** closes it again and discards what was typed.

**Sensitive.** It becomes a switch row: label "Sensitive", hint "Hidden in lists until
revealed. Turn off for plain config such as ports or feature flags." The default stays on for
every type (author's call: the secure default).

**Masking.** The editors show what is typed, as today. Nothing new is rendered for values that
were not revealed.

## Tests

- **CLI** (with a fake API and a temp user config):
  - `--api-url` replaces a different default and prints the change.
  - The same URL prints nothing extra.
  - `.anchor.json` still never writes the default.
  - `ANCHOR_API_URL` does not replace an existing default.
  - `--json` includes `defaultApiUrl`.
  - A non-JSON 404 names the origin.
- **Web, component and route tests:**
  - Each editor round-trips its string.
  - List: paste-split, and dropping empty rows.
  - Boolean starts unselected.
  - JSON Format button.
  - PEM file load (with a `File`) and the detected-block hint.
  - Error after blur, not before.
  - Type switching rules.
  - Edit mode: closed row sends no value; Replace then Keep sends no value; Reveal loads.
  - The CLI login page shows the email, the code tile, three rows and equal buttons.
  - The OAuth page uses the shared list.
- The dashboard-ui checklist passes on the diff (tokens only, sentence case, no unmasked
  values).

## Release

- Version 0.5.1 for every manifest.
- CHANGELOG `Fixed` (login default, 404 message) and `Changed` (CLI login page, secret
  editors).
- The release itself (tag and publish) waits for the owner's go-ahead, as before.
